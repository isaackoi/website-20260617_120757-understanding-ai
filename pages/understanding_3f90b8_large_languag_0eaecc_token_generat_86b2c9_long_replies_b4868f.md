## Introduction

Long AI answers take longer to appear for a simple reason: the model does not create the entire response at once. Instead, it generates one token at a time, and every additional token requires another [prediction]({{ 'error-harms/' | relative_url }}) step. What appears on screen as a flowing paragraph is actually a rapid sequence of individual [decisions]({{ 'decisions/' | relative_url }}), each based on the prompt and everything generated so far. Because generation is inherently sequential, a 500-token answer requires roughly five times as many generation steps as a 100-token answer. This token-by-token process is one of the main reasons output length has a strong effect on response time.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://arxiv.org/html/2604.07023v1" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: arxiv.org">[arXiv+2Wayland Zhang]</a><span class="citation-popover" role="note"><span class="citation-popover-source">arxiv.org</span><span class="citation-popover-snippet">Enabling Autoregressive Models Multi-Token Generation8 Apr 2026 — Autoregressive (AR) language models spend the same compute on ever...</span></span></span>

## The repeated cost of each new token

When a language model generates text, it performs a prediction cycle for every token it outputs. After producing one token, it must immediately run another prediction to determine the next one. The process repeats until the answer is complete. Unlike many computing tasks, these prediction steps cannot simply be generated all at once because each new token depends on the tokens that came before it.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://waylandz.com/llm-transformer-book-en/chapter-16-training-vs-inference/" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: waylandz.com">[Wayland Zhang+2NVIDIA Developer]</a><span class="citation-popover" role="note"><span class="citation-popover-source">waylandz.com</span><span class="citation-popover-title">Wayland Zhang Chapter 16: Training vs Inference</span><span class="citation-popover-snippet">Wayland ZhangChapter 16: Training vs Inference - Why Generation Is One...Training processes the full known sequence in parallel; inferen...</span></span></span>

A useful way to think about it is as a chain:

1. Generate token 1.<span class="citation-chip-wrap"><a class="citation-chip" href="https://waylandz.com/llm-transformer-book-en/chapter-16-training-vs-inference/" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: waylandz.com">[waylandz.com]</a><span class="citation-popover" role="note"><span class="citation-popover-source">waylandz.com</span><span class="citation-popover-title">Wayland Zhang Chapter 16: Training vs Inference</span><span class="citation-popover-snippet">Wayland ZhangChapter 16: Training vs Inference - Why Generation Is One...Training processes the full known sequence in parallel; inferen...</span></span></span>
2. Add token 1 to the context.
3. Generate token 2.<span class="citation-chip-wrap"><a class="citation-chip" href="https://waylandz.com/llm-transformer-book-en/chapter-16-training-vs-inference/" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: waylandz.com">[waylandz.com]</a><span class="citation-popover" role="note"><span class="citation-popover-source">waylandz.com</span><span class="citation-popover-title">Wayland Zhang Chapter 16: Training vs Inference</span><span class="citation-popover-snippet">Wayland ZhangChapter 16: Training vs Inference - Why Generation Is One...Training processes the full known sequence in parallel; inferen...</span></span></span>
4. Add token 2 to the context.
5. Repeat until the response ends.

If a model generates 50 tokens, it performs approximately 50 [decoding]({{ 'decoding/' | relative_url }}) steps. If it generates 500 tokens, it performs approximately 500 decoding steps. The relationship is not perfectly linear because of hardware and implementation details, but longer outputs generally require proportionally more work.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://arxiv.org/html/2604.07023v1" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: arxiv.org">[arXiv+2NVIDIA Developer]</a><span class="citation-popover" role="note"><span class="citation-popover-source">arxiv.org</span><span class="citation-popover-snippet">Enabling Autoregressive Models Multi-Token Generation8 Apr 2026 — Autoregressive (AR) language models spend the same compute on ever...</span></span></span>

This is why output length often dominates perceived latency. In production systems, the time spent generating completion tokens can exceed the time spent reading the original prompt.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://medium.com/%40gezhouz/understanding-llm-response-latency-a-deep-dive-into-input-vs-output-processing-2d83025b8797" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: medium.com">[Medium]</a><span class="citation-popover" role="note"><span class="citation-popover-source">medium.com</span><span class="citation-popover-title">This has several practical implications.Read more</span><span class="citation-popover-snippet">Understanding LLM Response Latency: A Deep Dive into...July 16, 2025 — The key insight is that output token latency is dramaticall...</span><span class="citation-popover-meta">Published: July 16, 2025</span></span></span>

### Why generation cannot be fully parallelised

During training, models can process many positions in a sequence simultaneously because the correct text is already known. During inference—the stage where a chatbot is answering a user—future tokens do not yet exist. The model must wait for each prediction before it can make the next one. This serial dependency creates a fundamental speed limit.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://waylandz.com/llm-transformer-book-en/chapter-16-training-vs-inference/" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: waylandz.com">[Wayland Zhang]</a><span class="citation-popover" role="note"><span class="citation-popover-source">waylandz.com</span><span class="citation-popover-title">Wayland Zhang Chapter 16: Training vs Inference</span><span class="citation-popover-snippet">Wayland ZhangChapter 16: Training vs Inference - Why Generation Is One...Training processes the full known sequence in parallel; inferen...</span></span></span>

As a result, generating 1,000 tokens is not merely displaying more text. It requires roughly 1,000 successive prediction cycles.

## Why the context keeps growing

Long replies involve more than just additional prediction steps. Every newly generated token becomes part of the context that future [predictions]({{ 'predictions/' | relative_url }}) must consider.

Suppose a chatbot has already produced several paragraphs. When it predicts the next token, it does not ignore those paragraphs. Instead, it incorporates the growing conversation history and generated response into its calculations. The effective sequence becomes longer with each step.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://codefinity.com/courses/v2/54a749e2-1829-4bce-b9b7-1fedaaa1fd65/3fa311cb-f2e0-4fb1-ae9b-c5baee8d11ad/635bf5e1-1149-4701-88c8-0c36baa69e7b" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: codefinity.com">[Codefinity]</a><span class="citation-popover" role="note"><span class="citation-popover-source">codefinity.com</span><span class="citation-popover-snippet">Learn Autoregressive Generation MechanismHidden states in transformers carry forward the context from earlier tokens at each ge...</span></span></span>

Without optimisation techniques, this growth would become extremely expensive. A naive implementation would repeatedly recalculate information about all previous tokens during every generation step. Researchers often use examples where the amount of text that must be reconsidered grows continuously as generation progresses.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://mbrenndoerfer.com/writing/autoregressive-generation-gpt-text-generation" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: mbrenndoerfer.com">[Michael Brenndoerfer]</a><span class="citation-popover" role="note"><span class="citation-popover-source">mbrenndoerfer.com</span><span class="citation-popover-title">The first generated token requires processing 50 tokens.Read more</span><span class="citation-popover-snippet">Michael BrenndoerferAutoregressive Generation: How GPT Generates Text...28 Jul 2025 — With naive generation, each step requires a full f...</span></span></span>

The practical consequence is that:

* A short answer has a relatively small working context.
* A long answer creates a much larger working context.
* Larger contexts generally require more memory and data movement.
* More memory usage can reduce overall throughput and increase latency.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://arxiv.org/html/2505.13109v4" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: arxiv.org">[arXiv+2arXiv]</a><span class="citation-popover" role="note"><span class="citation-popover-source">arxiv.org</span><span class="citation-popover-snippet">Boosting KV Cache Retrieval for Efficient LLM InferenceFeb 28, 2026 — However, long contexts pose significant deployment challenges...</span></span></span>

Studies of long-context inference consistently find that latency tends to rise as sequence length increases, creating a trade-off between using more context and maintaining fast response times.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://arxiv.org/html/2501.12372v6" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: arxiv.org">[arXiv]</a><span class="citation-popover" role="note"><span class="citation-popover-source">arxiv.org</span><span class="citation-popover-title">arXiv Is Long Context All You Need?</span><span class="citation-popover-snippet">Leveraging LLM&#x27;s...Latency increases (near) linearly with context size, hence there is a clear trade-off between latency and better accu...</span></span></span>

### A practical example

Imagine two chatbot replies generated by the same model:

* Reply A: 100 tokens.
* Reply B: 1,000 tokens.

Reply B requires roughly ten times as many generation steps. In addition, the later stages of Reply B operate over a much larger accumulated context. Even though modern optimisations reduce the cost dramatically, the model still performs substantially more work overall.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://arxiv.org/html/2604.07023v1" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: arxiv.org">[arXiv+2Hugging Face]</a><span class="citation-popover" role="note"><span class="citation-popover-source">arxiv.org</span><span class="citation-popover-snippet">Enabling Autoregressive Models Multi-Token Generation8 Apr 2026 — Autoregressive (AR) language models spend the same compute on ever...</span></span></span>

This is why lengthy essays, detailed reports, and long code outputs usually stream for longer than short factual answers.

## How hardware and optimisation hide the loop

If every generation step required a complete recomputation of all previous work, chatbot responses would be far slower than they are today. Modern systems rely on several engineering techniques to reduce the cost.

The most important is key-value (KV) caching. Instead of recalculating internal representations for previously generated tokens every time a new token is produced, the model stores reusable information from earlier steps. When generating the next token, it can reuse those cached values rather than starting from scratch.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://huggingface.co/blog/not-lain/kv-caching" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: huggingface.co">[Hugging Face+2Introl]</a><span class="citation-popover" role="note"><span class="citation-popover-source">huggingface.co</span><span class="citation-popover-snippet">Hugging FaceKV Caching Explained: Optimizing Transformer Inference...Jan 30, 2025 — Key-Value caching is a technique that helps speed up...</span></span></span>

KV caching significantly speeds up autoregressive generation, but it introduces its own trade-off. The cache grows as the context becomes longer, increasing memory requirements and placing pressure on memory bandwidth. For very long contexts, cache management becomes a major engineering challenge.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://arxiv.org/abs/2603.20397" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: arxiv.org">[arXiv+2arXiv]</a><span class="citation-popover" role="note"><span class="citation-popover-source">arxiv.org</span><span class="citation-popover-title">arXiv KV Cache Optimization Strategies for Scalable and Efficient LLM Inference</span><span class="citation-popover-snippet">arXiv KV Cache Optimization Strategies for Scalable and Efficient LLM Inference</span></span></span>

* Cache compression.
* More efficient memory layouts.<span class="citation-chip-wrap"><a class="citation-chip" href="https://medium.com/%40nraman.n6/estimating-llm-inference-memory-requirements-3ab599b7284b" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: medium.com">[medium.com]</a><span class="citation-popover" role="note"><span class="citation-popover-source">medium.com</span><span class="citation-popover-snippet">y 2–3× · The 2.6GB rule: Each 1K tokens per concurrent...Read more...</span></span></span>
* Faster GPU memory access.
* Speculative decoding, which attempts to generate multiple likely tokens ahead of time.
* Specialised inference hardware and batching strategies.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://developer.nvidia.com/blog/an-introduction-to-speculative-decoding-for-reducing-latency-in-ai-inference/" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: developer.nvidia.com">[NVIDIA Developer+2NVIDIA Developer]</a><span class="citation-popover" role="note"><span class="citation-popover-source">developer.nvidia.com</span><span class="citation-popover-snippet">NVIDIA DeveloperAn Introduction to Speculative Decoding for Reducing...17 Sept 2025 — The core latency bottleneck in standard autoregres...</span></span></span>

These optimisations can make generation feel much faster, but they do not eliminate the underlying sequential loop. The model still needs to produce the final answer token by token.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://developer.nvidia.com/blog/an-introduction-to-speculative-decoding-for-reducing-latency-in-ai-inference/" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: developer.nvidia.com">[NVIDIA Developer]</a><span class="citation-popover" role="note"><span class="citation-popover-source">developer.nvidia.com</span><span class="citation-popover-snippet">NVIDIA DeveloperAn Introduction to Speculative Decoding for Reducing...17 Sept 2025 — The core latency bottleneck in standard autoregres...</span></span></span>

## What the user experiences

From a user's perspective, a chatbot often appears to “type” its answer. That visible stream is a direct reflection of the generation process.

A short response may complete in a fraction of a second because relatively few prediction steps are needed. A long response may continue streaming for several seconds because hundreds or thousands of tokens must be generated one after another. Even on powerful hardware, each extra token adds another prediction cycle and slightly enlarges the context that future predictions must consider.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://medium.com/%40gezhouz/understanding-llm-response-latency-a-deep-dive-into-input-vs-output-processing-2d83025b8797" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: medium.com">[Medium+2Databricks]</a><span class="citation-popover" role="note"><span class="citation-popover-source">medium.com</span><span class="citation-popover-title">This has several practical implications.Read more</span><span class="citation-popover-snippet">Understanding LLM Response Latency: A Deep Dive into...July 16, 2025 — The key insight is that output token latency is dramaticall...</span><span class="citation-popover-meta">Published: July 16, 2025</span></span></span>

The key idea is that a long answer is not a single object waiting to be revealed. It is the result of many fast but sequential prediction steps.
